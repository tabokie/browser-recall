- I am actually thinking about something else:

We remove qbTree (keep the core functionality/UI code just in case we need it in the future, but make it dead code). And replace it with two sections: queries and filters.

One query are simple text search just like a Google search UI. We support exact match for quoted string. When there are multiple words in a query, we search for item that has all of the words (AND operator).

Different from Google search, we support saving a search, and save multiple searches. Results from different searches are OR-ed together.

Filters differ from search in that they are pre-defined. To start, we have filters like (1) toggle whether display notes, toggle whether display pages, (2) a range slider for creation time, a range slider for modified time / referenced time, (3) a set of bubble toggle of list names, which are the lists the results belong to. When page toggle is selected, additional filters such as (1) boolean predicates (have highlights, visited multiple times, have children, etc) (2) range slider for attention such as like count.

Conceptually, the time chart is a part of filters.

The final UI looks something like this:

[ "saved search 1"                      ] x
[ "search 2"                            ] x
[ // empty text input                   ] <save button>
|             time chart                  |
<filter icon>
create time  ----------------*======*------
(list-1)  (list-2)  (list-3)
[x] note
[ ] page

Filters are hidden by default, controlled by the filter icon button.
