- There is a plan to implement cross-device synchronization earlier at sync-plan.md. Since then, I have additional thoughts to extend this functionality to cross-user synchronization, the idea is this:

Due to the nature of log-based architecture, synchronization is equivalent to the publish and subscribe of logs. The same functionality can be used to share changes between different users. The access control is delegated to the specific storage (e.g. github auth).

There are creative ways to use the sharing capability. User can publish their entire history, or only publish changes related to a list. Likewise, user can subscribe another user's entire data, or only a list subset of it.

In both sync and share model, the actual username is preserved and rendered (e.g. for notes, for lists, for pins). But the interesting thing is how the list entity can diverge. For example, A subscribes B's list (with id generated by B), that list is marked as "created by B", and distinguishes itself from A's own lists. Then A moves that list under a different location, or delete it. A will continue to receive changes from B, even though the two diverges on how the list is positioned in the hierarchy.
